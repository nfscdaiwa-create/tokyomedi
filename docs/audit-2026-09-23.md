# TOKYO MEDI audit and release record — 2026-09-23

## Scope and evidence

- Production site: `https://tokyomedi.com/`; source: `nfscdaiwa-create/tokyomedi` on GitHub; deployment: Cloudflare Worker `tokyomedi` connected to `main`.
- Baseline mobile Lighthouse on `/en`: performance 93, accessibility 96, best practices 92, SEO 100; FCP 1.9 s, LCP 2.7 s, TBT 0 ms, CLS 0. These are single-run lab measurements, not field data.
- All 147 localized routes (49 each in Chinese, English, Japanese) were exercised locally, including canonical URLs, language tags, and internal links.
- All 16 linked PMDA professional sources and all 7 linked hospital sources responded successfully during this audit. A reachable URL alone does not establish that every clinical statement remains current.
- All 21 linked health-product pages were checked against their visible or structured SKU. All 21 product image URLs returned an image response.

## Confirmed defects and changes

1. **HTTP remained on HTTP.** The production root redirected an HTTP request to another HTTP URL. The Worker now upgrades production HTTP requests to HTTPS, uses HSTS on HTTPS responses, and preserves query strings. Local HTTP preview omits HSTS.
2. **Medicine image requests could stall.** On cold cache, live medicine-image requests took roughly 6.9–8.4 s and sometimes returned the generic fallback after scraping an unrelated retailer. Medicine pages now use an immediate deterministic reference card. The linked PMDA product information remains the authoritative reference; the card does not claim to show actual packaging.
3. **Health product images were slow and fragile.** They now use direct image URLs recorded from the linked product pages, with a four-second upstream timeout, content-type and size limits, a cache, and a short-lived fallback.
4. **Thirteen health-product SKUs differed from their linked source pages.** One collagen SKU was a local invented code; twelve other records used incorrect numeric codes, with several collisions. They were corrected to source-page values. A uniqueness check now prevents the duplicate-SKU failure mode from recurring.
5. **Two dosage forms were imprecise.** The Rybelsus record is an oral tablet, and the pediatric Entresto form is a granule tablet. The displayed forms are localized in all three languages and checked against the linked PMDA product sources.
6. **Accessibility issues were reproducible.** Text with reduced opacity, low-contrast labels, clipped mobile navigation, a mislabeled logo link, and skipped heading levels appeared across representative pages. These were corrected. Local mobile Lighthouse accessibility now scores 100 on home, medicine list, health list, inquiry, travel, sources, a medicine detail, and a guide detail.
7. **Inquiry copy asked for institution credentials.** The form now asks only for optional public licence registration information and warns against emailing patient data, passwords, ID scans, or confidential documents. The form still prepares an email in the visitor's mail client; it does not send or store the message.
8. **Search and language links accepted unnecessarily large inputs.** Search now normalizes full-width Latin characters and limits query length. Language-switch and inquiry prefill parameters are bounded. Root language selection respects `Accept-Language` quality weights and varies correctly by that header.
9. **Cloudflare Web Analytics was blocked by the CSP.** The CSP now permits the Cloudflare Insights script and its collector while keeping other origins constrained. Inline script/style remains allowed because the current site renders both inline; removing that allowance requires a separate asset/nonce migration.
10. **An unsupported origin claim appeared on health pages.** Origin is now displayed only where the record has explicit source data.

## Decisions and tradeoffs

- The existing small Cloudflare Worker was retained. A framework migration would add build and deployment complexity without solving the observed defects.
- Medicine images were replaced with reference cards because the previous third-party scrape could be slow and could imply a packaging match that had not been verified. A later image program should use licensed, product-specific manufacturer or PMDA assets and explicit editorial review.
- Health product pictures remain linked to the product-source host. The Worker caches successful responses and handles upstream failures; image rights and source-host availability still depend on that publisher.
- Medical content was checked at the source-link and representative-field level. Clinical review by a licensed professional, regulatory advice, and an audit of every historical statement were outside the available evidence and are not implied by this release.

## Verification gates

- `npm test`: route, search, locale, safety, media-failure, metadata, and regression checks pass.
- `wrangler deploy --dry-run`: Worker bundle builds successfully.
- Local browser: medicine search → detail → language switch and inquiry-email preparation worked; mobile navigation remained visible.
- Local Lighthouse: eight representative page types score 100 for accessibility. Final production performance and correctness must be verified after Cloudflare deploy, since local Lighthouse does not include production network behavior.

## Follow-up risks

- A remote health-image host may change URLs or fail. The Worker will show a branded fallback; periodically re-check all 21 URLs.
- Editorial dates on source pages may change after this audit. Use the PMDA and hospital links as live references and re-verify at a defined cadence.
- The CSP still permits inline JavaScript and CSS. Consider moving them to immutable assets or adopting CSP hashes/nonces when a build pipeline is introduced.
